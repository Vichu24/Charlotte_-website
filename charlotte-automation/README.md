## Setup

```bash
npm install
npx playwright install --with-deps
cp .env.example .env        # then edit values as needed
```

## Running tests

```bash
npm test                    # full suite, all projects
npm run test:smoke          # only @smoke-tagged tests
npm run test:regression     # only @regression-tagged tests
npm run test:e2e            # tests/e2e only
npm run test:headed         # see the browser
npm run test:ui             # Playwright's interactive UI mode
npm run test:debug          # step through with the inspector
npm run test:chrome         # single browser
npm run test:mobile         # mobile-chrome + mobile-safari projects
npm run test:staging        # ENV=staging (default)
npm run test:prod           # ENV=production
```

## Reports

- HTML: `npm run report` (opens `reports/html-report`)
- JSON: `reports/results.json`
- JUnit XML (for CI dashboards): `reports/junit-results.xml`
- Allure (if you run `allure generate reports/allure-results`)

Failed tests automatically keep a trace (`test-results/**/trace.zip`,
viewable with `npx playwright show-trace <path>`), a screenshot, and video.

Each test run appends structured JSON lines to `logs/api.log` (fetch/XHR
requests and responses), `logs/performance.log` (response status and duration),
and `logs/error.log` (failed requests, HTTP errors, browser errors, and failed
tests). Query strings and URL fragments are omitted to avoid recording
potentially sensitive values. Email, phone, card, and credential-like values
are redacted; logs use asynchronous writes and rotate at the start of a run
when a file exceeds 5 MB. Generated log files and rotations are ignored by Git.

TLS certificate checks remain enabled by default. Set
`IGNORE_HTTPS_ERRORS=true` only for a trusted test environment with a known
certificate issue. Successful payment tests are disabled unless explicitly
enabled with `RUN_PAYMENT_SUCCESS_E2E=true`; they never run against production.

Run isolated Node.js utility tests with `npm run test:unit`. Browser tests run
independently in parallel by default; set `WORKERS` to cap concurrency.
Unknown `ENV` values and malformed URLs fail fast rather than silently running
against staging. CI uploads sanitized runtime logs alongside the test reports.

## Adding a new test case from the sheet

1. Add/confirm the page object in `pages/` for whatever screen the case covers.
2. Add its test data to the matching file in `testdata/` (or extend
   `siteRoutes.json` for a simple navigation case).
3. Add a `test()` in the right folder under `tests/` (`smoke`, `regression`,
   or `e2e`) using the `test`/`expect` from `fixtures/pageFixtures.js`.
4. Tag it `@smoke`, `@regression`, or `@e2e` in the `describe` block so it's
   picked up by the matching npm script.

**Note on ID overlap:** the source sheet's TS-06 (Payment) tab re-numbers

happen to share IDs in the sheet itself - `payment.spec.js` prefixes every
title with "Payment -" so reports never conflate the two.

**Of the 241 generated tests, 30 are marked `test.fixme(...)`** rather than
given a fake-passing UI assertion, each with a one-line reason. These fall
into two groups:
- **Backend/external verification** - enrollment records, audit logs,
  confirmation email/SMS delivery, admin-configured fixture data (a known
  permit-required package, a known deposit amount, etc.). These need an
  API/DB check or an email/SMS-testing service, not a browser assertion.
- **Missing test fixtures** - file uploads (valid JPG, oversized file,
  unsupported format) need real sample files added under a `testdata/`
  fixtures folder before they can run.

**Every other page object beyond `HomePage`** (`PackageListingPage`,

swap in exact selectors (ideally `data-testid`) where a locator doesn't
match - the architecture and 1:1 test traceability are already in place.

then run with `ENV=uat npx playwright test`.
